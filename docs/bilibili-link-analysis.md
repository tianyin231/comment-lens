# B 站视频分享链接分析：接入核验与当前边界

核验日期：2026-09-30。保留此前小黑盒长文修复；其真机验收按本轮要求暂缓。此阶段仅面向 B 站视频分享链接，不包含动态、弹幕、直播、抖音或小红书。

## 获取方式核验结论

**尚未取得允许且可靠的真实评论正文来源，不能交付已经可用的 B 站“前 N 条评论风向”。** 当前会话没有 B 站获批开发者应用、评论读取权限或相应官方接口文档，也没有可用的授权凭据。产品必须显示获取阻碍和未分析状态。

## 当前实现与统计约定

当前实现：

- 首页新增“B站视频链接”，也可接收系统 `text/plain` 分享。分享内容仅填入输入框，用户点击“检查链接与获取条件”后才检查。
- 解析完整 HTTPS 视频链接、分享文字和 BV / av 编号；限定域名与视频路径、去除跟踪参数，拒绝账号信息、自定义端口、伪装域名、多目标链接、超长输入和非视频页面。格式识别不等于视频存在性验证。
- `b23.tv` 短链目前只识别并显示原因，不自动展开，不把短链当作已验证的视频；可由用户点击在浏览器打开。
- 可设置目标 N（1–200）和期望排序（热度 / 时间倒序）；生产来源固定为 `UnavailableBilibiliSource`，不装配未核验的 HTTP 评论适配器。界面显示实际读取 0 条、平台总数未知、实际排序未取得、楼中楼未读取、情绪比例尚未分析。
- 内部分页器仅通过明确可用的来源读取：按评论 ID 去重、保持返回顺序；遇重复游标、没有新增评论、排序不一致、格式错误、20 页上限或来源失败停止，保留已经取得的数据并标明不完整。
- 独立风向逻辑按已判断的顶层评论 ID 统计，同文只上传一次但分别计入对应评论 ID。没有文字的评论跳过，不算中性；没有实际评论时不调用 Jev。每批至多 8 段独立文字，任一接口失败即停止后续批次，保留已完成结果，不自动重试。
- 输入、N、排序或分享目标改变后取消旧任务并清空旧结果；Activity 销毁后忽略迟到回调。B 站流程不写入小黑盒的五帖缓存，也不依赖无障碍或悬浮窗权限来检查链接。

实现中的分页和风向逻辑用于等待允许来源接入，不能据此把当前 APK 宣传为已能读取真实 B 站评论。

对未来接入的允许来源，前 N 条以指定排序下的顶层评论为目标，不能把楼中楼预览或置顶补充列表混入排序后的数量。产品需分别展示目标 N、请求排序、实际排序是否确认、实际取得数量、已判断数量、回复覆盖和失败原因。

获取为 0 时，不能推断视频没有评论、不能显示“0% 正面 / 0% 负面”暗示判断成功。分页中途失败时保留已获得的真实数据并标明不完整；获取失败与情绪接口失败分开说明。未获得评论正文时不调用 Jev。

## 解除阻碍需要的证据

1. 平台允许该应用读取评论正文的接口文档及获批权限范围；明确是否仅适用于授权作者的视频。
2. 经适当配置提供访问条件，不把应用 secret 或用户凭据硬编码进 APK、仓库、日志或测试夹具。
3. 使用获准方式验证真实视频的至少两页评论，确认分页终止、稳定评论 ID、排序、置顶处理及回复覆盖。
4. 如实记录登录、限流、访问拒绝、评论关闭、空列表与部分获取；通过后才启用生产评论来源。

纯本地解析、分页和失败状态测试只能证明程序行为，不能证明已取得平台访问权限，也不能证明真实接口可用。无需通过真机来运行这些测试；真实网络与授权来源验证仍是独立前提。
